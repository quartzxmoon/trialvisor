# Tests

## Test 1 - First-time onboarding reaches a protection center [sanity]
Viewport: desktop (1280x800)
Covers: AppDeploy authentication, bounded authenticated startup, recoverable dashboard loading, Trialvisor account initialization, resumable onboarding, branded landing, first-visit guidance
Description: Verifies the first-run path is branded, secure, persistent, and does not confuse Trialvisor authentication with connected inbox authorization.

Steps:
1. Sign in with a new Trialvisor identity
2. Review the Welcome setup screen and refresh the page
3. Continue to the dashboard without connecting an inbox

Expected: The user sees the Trialvisor logo and onboarding until explicitly continuing, then reaches What could charge me next; an authenticated reload shows a branded loading state without rendering incomplete dashboard data, load failure offers Retry and Sign out controls within 15 seconds, returning users do not repeat signup, and first-visit guidance does not spam.

## Test 2 - Manual discovery review requires explicit Protect
Viewport: desktop (1280x800)
Covers: manual trial creation, review-only state, Safe Cancel Deadline display, Protect confirmation, authorization persistence
Description: Verifies a manually added trial becomes reviewable but cannot gain cancellation authority until the user confirms Protect.

Steps:
1. Add a manual trial for Canva Pro at $14.99 per month with a future trial end date
2. Open the Protect flow and review the Safe Cancel Deadline, annualized cost, planned action, and cancellation tier
3. Select Protect this trial and refresh

Expected: The trial moves from Protection Needed to protected only after the explicit confirmation, the authorization remains after refresh, and first-Protect guidance is shown at most once.

## Test 3 - Keep decisions and billing gates stay neutral and durable
Viewport: desktop (1280x800)
Covers: protected-trial decision UX, KEEP path, scheduled cancellation revocation, duplicate-execution guardrail, Stripe configuration gate, webhook-derived billing status
Description: Verifies the decision surface preserves the selected state and paid access cannot activate before Stripe is fully configured and webhook-verified.

Setup:
1. Add and protect a manual trial through the UI

Steps:
1. Open Review decision
2. Select Keep service
3. Refresh the dashboard and inspect Protection history
4. Open Plan & billing

Expected: The service is marked Kept, scheduled cancellation is revoked, the choice remains visible in history, no cancellation is presented as completed, the Free plan remains active, and paid checkout is disabled while Stripe secrets and prices are unconfigured.

## Test 4 - Connected Google account shows bounded discovery validation state
Viewport: desktop (1280x800)
Covers: Google OAuth connection state, bounded Gmail sync, incremental checkpoint fallback search, deduplication, real-mailbox validation status
Description: Verifies Gmail synchronization remains privacy-minimized, avoids unnecessary full rescans after an unchanged history checkpoint, and does not claim real discovery verification without a persisted matched mailbox finding.

Steps:
1. Connect Google through production OAuth
2. Select Sync from Connected accounts
3. Review the discovery validation message and sync again

Expected: Connection identity and last sync remain visible, an unchanged incremental sync visibly reports that Gmail supplied no new messages without repeating the two-year search, repeated sync does not duplicate findings, and the UI shows the controlled test-message instructions while real mailbox discovery remains pending.

## Test 5 - Mobile protection flow remains usable during provider failure
Viewport: mobile (375x667)
Covers: responsive navigation, mobile discovery review, accessible modal behavior, persistent critical error state, Gmail provider failure safety
Description: Verifies critical protection controls remain reachable on phone, a failed inbox sync cannot change authorization state, and an unsupported cancellation adapter cannot create a verified result.

QA Faults:
```json
[
  {
    "method": "POST",
    "path": "/api/gmail/sync",
    "status": 503,
    "body_json": { "error": "gmail_temporarily_unavailable" }
  }
]
```

Setup:
1. Add and protect a manual trial through the UI

Steps:
1. Open mobile navigation and select Connected accounts
2. Select Sync for Google
3. Return to Protection center, review the protected trial, and select Cancel as planned

Expected: A persistent Gmail error is shown, navigation and modal controls remain usable at 375px width, the failed sync grants no authorization, and cancellation moves to Action Required without verified evidence or confirmed savings because no production provider adapter is enabled.
